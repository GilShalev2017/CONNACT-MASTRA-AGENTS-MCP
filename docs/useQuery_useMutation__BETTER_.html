useQuery / useMutation (TanStack Query) vs. Raw fetch / axios

Advantages of TanStack Query

Feature TanStack Query Raw fetch / axios
Caching Results are cached by query key. Repeat requests for the same data are served instantly instead of re-fetching. ❌ Must implement caching yourself.
Request Deduplication Multiple components requesting the same data simultaneously trigger only one network request. ❌ Each component issues its own request.
Background Refetching Automatically refetches on window focus, reconnect, intervals, or when data becomes stale. ❌ Manual polling/refetch logic required.
Loading & Error State Built-in isLoading, isFetching, isError, etc. No useEffect boilerplate needed. ❌ Must manage loading/error state manually.
Retries & Backoff Automatic retries with configurable exponential backoff. ❌ Must implement retry logic yourself.
Optimistic Updates & Cache Invalidation useMutation supports optimistic UI updates, rollback on failure, and invalidating related queries after mutations. ❌ Must manually update UI and cached data.
Request Cancellation Automatically cancels stale requests when components unmount or query parameters change. ❌ Must use AbortController or similar manually.
DevTools Built-in DevTools for inspecting query cache and request state. ❌ No built-in debugging tools.

Summary:
Raw fetch or axios only performs the HTTP request. Everything else—caching, retries, loading states, deduplication, refetching, optimistic updates, and cache invalidation—must be implemented manually.

When are they called?

useQuery

Used for reading data (GET-like requests).

Characteristics

  • Runs automatically when the component mounts.
  • Re-runs whenever the queryKey changes.
  • Can automatically refetch when:
    • the window regains focus,
    • the network reconnects,
    • data becomes stale,
    • a polling interval is configured.
  • Declarative—you describe what data you need, not when to fetch it.
const { data, isLoading } = useQuery({
  queryKey: ["users"],
  queryFn: fetchUsers,
});

useMutation

Used for changing data (POST, PUT, PATCH, DELETE) or any side effects.

Characteristics

  • Does not run automatically.
  • Returns a mutate() / mutateAsync() function.
  • You call it imperatively, typically from:
    • button clicks,
    • form submissions,
    • user actions.
const mutation = useMutation({
  mutationFn: createUser,
});

<button onClick={() => mutation.mutate(user)}>
  Create User
</button>

After a successful mutation, you’ll usually invalidate related queries so they refetch fresh data:

const queryClient = useQueryClient();

const mutation = useMutation({
  mutationFn: createUser,
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["users"] });
  },
});

Rule of Thumb

useQuery useMutation
Read data Modify data
GET requests POST / PUT / PATCH / DELETE
Runs automatically Triggered manually
Declarative Imperative
Keeps cache fresh Updates server, then refreshes/invalidate cache

Easy way to remember:

  • useQuery = Automatic + Read data
  • useMutation = Manual + Change data
